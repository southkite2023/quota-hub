# 首次国内商店发布准备

核查日期：2026-09-30。目标：个人开发者，优先小米 / vivo / OPPO。当前验证版本为 0.7.1+9，已准备 [Releases 草稿](https://github.com/southkite2023/quota-hub/releases/tag/untagged-a6832dd4cbd18d529ba1)（需仓库权限，未公开）。工程 Release 模式不等于已经完成正式版验收或商店审核。

## 包体优化与提交包

0.7.0 公开 APK 为 Debug 通用测试包，150,865,308 字节（150.87 MB / 143.88 MiB）。0.7.1 改为 Release AOT，分离调试信息，输出通用包与 ARM64、ARMv7、x86_64 包；不删用户功能、不改变凭据存储。实测：通用包 48.80 MB（缩小 67.7%）、ARM64 17.02 MB（缩小 88.7%）、ARMv7 14.25 MB、x86_64 18.46 MB。详细字节数与 SHA-256 见 [包体报告](reports/0.7.1-apk-size.json)。

优先向允许单独 ARM64 包的商店提交 arm64-v8a 版；若该商店要求多架构兼容或当前账号不支持分别上传，则用通用 Release 包。ARM64 包不能安装在仅支持 32 位的设备上；x86_64 留作模拟器/对应设备验证，不作为普通手机首选。不要把压缩 ZIP 当作安装包，也不要直接把 AAB 当 APK 分发。

构建固定 Flutter 3.47.5 和 pubspec.lock；所有 APK 继续使用固定证书、包名 `com.example.quota_hub` 和构建号 9。后续须递增 versionCode，签名密钥须离线备份。Dart/R8 符号作为 CI 产物保留 90 天，本轮已另备份至被 Git 忽略的 `private/release-symbols/0.7.1/symbols.zip`，ZIP SHA-256 为 `00872b5668f2a2f6d57081e1f59ed1c6ffaf1cbb8697ddc7f7050ba25574b9ad`；正式发布前还应纳入个人离线备份，不能只依赖 Actions 到期产物。

## 已完成的工程验证

86 项 Flutter 测试、静态检查及各平台编译通过；四种 APK 通过固定签名、版本、非调试、ABI、AOT 与 ZIP/64 位 ELF 16 KB 对齐检查。Android 15 x86_64 模拟器全新安装和从 0.7.0 无账户状态升级启动通过。没有使用真实凭据，不能据此宣称真实账户迁移、厂商真机、小组件、长期后台或 16 KB 环境运行已验收。

## 提审前必须补齐

1. **身份、名称与包名**：个人开发者实名，确认目标商店接受本人的应用类别与资质。当前桌面名称 Quota Hub、项目称呼“U关于余额视图”，应确定统一正式名称、图标、运营者名称及有效联系方式。`com.example.quota_hub` 是模板式包名；正式备案前建议确定长期使用的唯一包名。一旦改包名，系统会视为新 App，旧版不能直接覆盖或访问原私有存储，须设计安全迁移；不得为改名泄露原 API Key。
2. **APP 备案与版权材料**：本应用联网查询第三方服务，不应自行认定为离线工具而免备案。按主管部门及接入服务商要求办理 APP 备案，登记名称、主体、包名与提交包一致。准备本人持有的软件著作权或商店接受的替代版权证明；各平台接受范围不同，不假设一张证书或授权能通用。网站 ICP 与 APP 备案不能笼统等同。未获得备案号码，不填假号。
3. **隐私政策和同意流程**：目前没有首次隐私同意、应用内独立隐私政策及备案展示入口。需提供易访问的简体中文政策网页、应用内同一版本全文、明确同意/拒绝，记录版本及同意状态，并把读取账户/查询等行为放在对应授权之后。政策据实说明 API Key、云密钥、余额缓存、所选服务商及自定义地址的数据流；“本机加密保存”不等于“不向网络发送”：部分接口会向服务商发送凭据。明确通知/后台刷新用途、移除本机数据方法、卸载影响、联系方式及第三方依赖；不要编造开发者主体、收集行为或承诺。
4. **真实功能与审核演示**：对外定位为账户余额/用量查看工具。AI 订阅分类不等于会员套餐查询；节点订阅目前只支持自定义余额 JSON，不支持订阅链接/流量/到期日；OpenAI 显示费用而非可用余额；智谱为实验性接口，硅基流动待适配。不得宣传未实现能力。正式版本应处理“待适配/实验性”入口，避免主要功能被判定为未完成。涉及节点服务的实际用途和服务范围需如实说明，不能通过改标签隐瞒功能。为审核准备可用的专用低权限测试账户或清楚标注的演示流程，不交出个人生产云密钥。
5. **真机和覆盖升级**：至少覆盖小米、vivo、OPPO 真机；检查首次同意/拒绝、账户增删改、错误/断网/过期缓存、零/负余额、多币种、从 0.7.0 覆盖后凭据可读、小组件点击/滚动、通知拒绝、后台停止、重启及省电限制。Release 会精简代码，必须验证后台 Dart 入口和组件；源码已保留 `@pragma('vm:entry-point')`，但这不能代替设备验证。另在 16 KB 页面环境验证，二进制对齐检查不能代替运行检查。
6. **后台刷新预期**：现有实现为 dataSync 前台服务，已处理 onTimeout；Android 15+ 对符合条件的服务有 24 小时内累计 6 小时限制，不应承诺全天候精确定时刷新。需验证超时提示、重新开启和厂商省电行为，必要时另设计系统任务调度。
7. **上架资料与维护**：准备真实截图、简介、权限用途、隐私政策链接、备案编号和客服/漏洞反馈入口；小米公开要求至少 4 张非重复截图。README/SECURITY 已更新为实际测试阶段状态，正式对外前继续核对下载入口和运营者联系方式。版权归属、图标授权、开源依赖许可证与隐私说明需一致。先小范围 Release 包验证，再确定正式版编号和提审；不以“构建成功”宣称“已通过商店审核”。

- [小米应用审核规范](https://dev.mi.com/xiaomihyperos/documentation/detail?pId=1080)：部分类别限制个人开发者，需按实际功能准确选类。

- [Flutter Android 发布](https://docs.flutter.dev/deployment/android)：Release、按 ABI 分包和签名。
- [Android 前台服务时限](https://developer.android.com/develop/background-work/services/fgs/timeout)、[16 KB 页面支持](https://developer.android.com/guide/practices/page-sizes)：后台与设备兼容性。
