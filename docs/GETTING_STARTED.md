# 开发从这里开始

当前没有启动命令：先完成项目骨架，再在 README 中提供经过验证的运行步骤。

## 第 1 步：确定实现边界与开发环境

确认采用 Flutter 主界面 + 原生小组件，或全部使用各平台原生控件。创建技术决策记录，列出最低系统版本、设备架构与构建环境。准备 macOS/Xcode、Android SDK 和 Windows 构建机；不要在这个阶段购买服务器或商店账号。

交付：框架决策记录、工具链检查结果、平台支持矩阵。

## 第 2 步：定义数据与模拟样例（第一个编码任务）

建立 packages/contracts，描述账户、供应商、指标、币种/单位、更新时间、错误及缓存状态。为余额、流量和到期时间建立虚构快照。覆盖正常、零、未知、过期和失败；示例不使用真实账户数据。

交付：协议文档、样例及字段验证。一份快照应能同时支持 App、网页和小组件。

## 第 3 步：验证 App 与系统组件

搭建客户端，先用模拟快照显示三张卡片。完成五端启动，然后每个系统完成一个最小组件及点击进入 App。Apple 使用 WidgetKit；Android 使用 Glance/AppWidget；Windows 验证 Provider 打包与小组件面板展示。

交付：各平台构建记录，以及安装、缓存、后台刷新、点击跳转证据。网页通过不代表移动端通过。

## 第 4 步：接入服务端和真实供应商

先完成认证与快照接口，再逐个接 DeepSeek、通用订阅、阿里云。用户仅通过私有配置填入凭据。使用获得授权的订阅进行私下联调，不把个人订阅加入仓库。

交付：真实数据闭环、限频/超时/重试、错误隔离、只读设备令牌撤销、凭据与日志脱敏测试。

## 第 5 步：完善使用体验

完善账户添加、排序、组件账户选择、金额隐藏和更新时间。加入 macOS 菜单栏与 Windows 托盘。先解决查看与配置，再扩展历史趋势和通知。

## 第 6 步：内测与发布

提供服务端自托管说明、演示模式和各平台构建文档。分别测试 iOS、Android、macOS、Windows、Web。准备签名与分发，发布安装产物和源码；商店账号及审核单独处理，不承诺所有商店同步通过。

## 可以直接使用的下一项任务

“为 Quota Hub 完成第 1、2 步：检查开发工具链，记录客户端框架决策，设计版本化数据协议和虚构快照，覆盖正常、零余额、缺失、过期与失败状态。暂不接入真实密钥，不把尚未实现的平台标为支持。”
