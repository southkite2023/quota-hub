# 版本编号规则

当前版本：**0.3.0**（2026-09-25，云账户余额功能更新，测试阶段）。

版本格式为 `主版本.功能版本.补丁版本`，采用用户指定的项目规则：

| 变更类型 | 递增位置 | 从 0.2.1 升级的示例 |
| --- | --- | --- |
| 补丁更新、问题修复、小范围调整 | 最后一位 +1 | 0.2.2 |
| 新功能或功能扩展 | 中间一位 +1，最后一位归零 | 0.3.0 |
| 大幅度 UI 修改、模块调整 | 第一位 +1，其余两位归零 | 1.0.0 |

每次更新先判断变更类型。同一版本含多种变更时，按最高级别递增；同一轮开发中的修正和重复构建不重复增加对外版本。用户明确指定版本号时优先采用指定值。

版本发布前同步更新 `apps/client/pubspec.yaml` 和 `CHANGELOG.md`。Flutter `+` 后的内部构建号用于安装升级，每次产出新的分发版本递增，独立于上述三段对外版本号；当前配置为 `0.3.0+4`。

已有安装包不可通过修改文档追溯改号。此前 0.2.0+2 安装包仍保持原编号；0.2.1 需由更新后的源码重新构建。登记版本号不等于已正式发布或完成真机验收。

## 更新日志要求

每次更新必须维护根目录 `CHANGELOG.md`，与版本配置保持一致。日志按版本由新到旧排列，记录：

- 版本号、日期、变更类型与发布/测试状态。
- 实际新增、调整、修复的内容及用户可见影响；无内容的分类省略。
- 已完成的验证及其对应版本，尚未完成的验收与已知限制。

同一轮更新的修正追加在同一版本条目下。仅补写日志不单独递增版本，不编造历史版本记录，不将计划功能写成已完成。
