# ADR 0001：客户端主界面技术路线

状态：拟采用，等待五端构建原型验证（2026-09-22）。

## 决策

以 Flutter 构建 iOS、Android、macOS、Windows 主程序和 Web 看板；系统组件分别采用 WidgetKit、Glance/AppWidget 和 Windows App SDK Widget Provider。主程序与原生扩展通过版本化快照协议交互。

选择理由：主界面可共享账户列表、状态呈现与配置逻辑；组件必须遵循各系统独立的打包、后台更新及点击行为。框架选择仅对主界面生效，不代表组件已经可用。

## 验证关口

1. 在对应构建机分别完成五端最小主程序的启动和安装。
2. Apple、Android、Windows 各完成一个读取模拟快照的原生组件；iOS 和 macOS 分别验收。
3. 验证组件点击打开相应账户、离线缓存、后台刷新和发布打包。
4. 若 Windows 组件的打包或 Flutter 桥接不可行，记录失败证据并调整该平台方案；不提前标记支持。

最低系统版本、设备架构和签名方案待各平台原型验证后填写。Flutter/Dart 版本待安装并锁定；此处不虚构版本号。
